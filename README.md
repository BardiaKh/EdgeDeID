# EdgeDeID

**Edge-deployable PHI de-identification for medical notes.**
A reproducible pipeline for distilling three frontier LLM "teachers" into a
small Qwen3 student that tags protected health information (PHI) with XML
entity markup, suitable for on-device or air-gapped deployment via
`llama.cpp`.

> Methodology: *Hybrid Distillation with Iterative Tagging.*
> Multiple teachers generate diverse synthetic notes, a first-pass student
> model is trained on raw teacher labels, that student then re-labels its own
> training corpus to correct teacher drift, and a final student is trained on
> the cleaned data with controlled augmentations.

---

## Why this exists

Real PHI data can't leave the hospital, and frontier LLMs can't be deployed
on-prem cheaply. Public PHI corpora (i2b2, MIMIC-DEID) are small and stylistic
mismatches with internal notes. Synthetic notes generated by many teachers,
cleaned via self-pseudo-labeling, give us a training corpus that:

1. is licensable (purely synthetic),
2. covers diverse note structures (each teacher hallucinates differently),
3. converges on consistent labeling (pseudo-labeling collapses teacher
   disagreement), and
4. supports cheap, fast inference (small student → quantized GGUF).

The end product is a **0.6B-parameter Qwen3 model** that runs in ~150ms per
note on CPU via `llama.cpp` with comparable PHI-tagging F1 to the much larger
teachers on held-out external data (see `evals/`).

## Pipeline at a glance

```
┌─ Stage 1: Generate ──────────────────────────────────────────────────────┐
│  data_prep/DataGeneration-{Haiku,DeepSeek,Hermes}.ipynb                  │
│   ↳ 3 frontier LLMs each emit ~10–25k synthetic (note, XML-tags) pairs   │
│   ↳ writes raw CSVs → data/{hermes,haiku,deepseek}/output_N_<teacher>.csv │
└──────────────────────────────────────────────────────────────────────────┘
                                  │
┌─ Stage 2: First-pass SFT ────────────────────────────────────────────────┐
│  SFT/sft.ipynb with MODEL_NAME = "Qwen/Qwen3-1.7B-Base"                  │
│   ↳ trained on small high-confidence subset                              │
│   ↳ produces a 1.7B "labeling" model                                     │
└──────────────────────────────────────────────────────────────────────────┘
                                  │
┌─ Stage 3: Pseudo-label ──────────────────────────────────────────────────┐
│  data_prep/pseudolabel.ipynb (vLLM-served 1.7B model)                    │
│   ↳ re-tags every synthetic note with the trained 1.7B model             │
│   ↳ writes data/<teacher>/<teacher>_pseudolabeled.csv                    │
└──────────────────────────────────────────────────────────────────────────┘
                                  │
┌─ Stage 4: Combine + augment ─────────────────────────────────────────────┐
│  data_prep/combine.ipynb (PSEUDO_LABEL=True)                             │
│   ↳ merges three teachers, applies date-format / name / phone aug.       │
│   ↳ pipeline.data.augmentations rotates labels through ~30 transforms    │
│   ↳ writes data/train.csv + data/test.csv                                │
└──────────────────────────────────────────────────────────────────────────┘
                                  │
┌─ Stage 5: Final SFT ─────────────────────────────────────────────────────┐
│  SFT/sft.ipynb with MODEL_NAME = "Qwen/Qwen3-0.6B-Base"                  │
│   ↳ trains the deployable 0.6B student on the full pseudo-labeled set    │
└──────────────────────────────────────────────────────────────────────────┘
                                  │
┌─ Stage 6: Quantize + serve ──────────────────────────────────────────────┐
│  llama.cpp convert_hf_to_gguf.py + quantize → Q4_K_M GGUF                │
│  demo/cli_anonymizer.py — terminal demo, llama.cpp backend               │
│  demo/gradio_demo.ipynb — web UI                                         │
└──────────────────────────────────────────────────────────────────────────┘
```

## Setup

Requires Python ≥ 3.10. The repo is managed with [uv](https://github.com/astral-sh/uv).

```bash
git clone https://github.com/BardiaKh/EdgeDeID.git
cd EdgeDeID
uv sync                       # installs all deps
uv sync --extra flash         # optional: flash-attn for faster SFT (needs CUDA toolchain)
```

Set API keys for the generation notebooks (skip any teacher you don't want
to regenerate):

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export DEEPSEEK_API_KEY=sk-...
export OPENROUTER_API_KEY=sk-or-...
```

## Data

- **Raw teacher CSVs** (`data/{teacher}/output_N_{teacher}.csv`) are
  committed — these are the immediate output of Stage 1 generation.
- **Per-teacher pseudo-labeled CSVs** (`data/{teacher}/{teacher}_pseudolabeled.csv`)
  are committed — these are the Stage 3 self-relabeled corpora that Stage 4
  consumes.
- **`data/train.csv` and `data/test.csv` are not committed.** They are
  produced by `data_prep/combine.ipynb` and are easy to regenerate (a few
  minutes on a laptop). To make them:

  ```bash
  jupyter lab data_prep/combine.ipynb
  # Run all cells with PSEUDO_LABEL = True (default)
  ```

  This will write `data/train.csv` (~108 MB) and `data/test.csv` (~700 KB).

If you want to regenerate from scratch (instead of using the committed
pseudo-labeled CSVs), run the notebooks in order: `DataGeneration-*` →
`pseudolabel.ipynb` (Stage 3, requires a trained 1.7B labeling model and a
running vLLM server) → `combine.ipynb`.

## Step-by-step workflow

### Stage 1 — Synthetic data generation

Each teacher samples from a controlled distribution of "report length" ×
"PHI features to include" criteria, then is asked to write a fake medical
note containing those features and emit a `<phi_entities>` block.

| Teacher    | API                                | Notebook                        | Prompt config                          |
|------------|------------------------------------|---------------------------------|----------------------------------------|
| Haiku      | Anthropic (batch API)              | `DataGeneration-Haiku.ipynb`    | `prompt-anthropic-rad-2.toml`          |
| DeepSeek   | DeepSeek chat API (OpenAI-compat)  | `DataGeneration-DeepSeek.ipynb` | `prompt-anthropic.toml`                |
| Hermes-405B | OpenRouter (free tier OK)         | `DataGeneration-Hermes.ipynb`   | `prompt.toml`                          |

Each notebook writes to `data/<teacher>/output_<N>_<teacher>.csv`. Increment
`N` for additional generation runs.

### Stage 2 — First-pass SFT (1.7B labeler)

`SFT/sft.ipynb` with `MODEL_NAME = "Qwen/Qwen3-1.7B-Base"`. The dataset cell
reads `data/train.csv` / `data/test.csv` — for the first pass, run
`combine.ipynb` once with `PSEUDO_LABEL = False` to get a "raw labels" version
of the dataset. Trains for ~1 epoch; output goes to
`SFT/data/Qwen3-1.7B-Base_SFT/checkpoint-XXXX/`.

### Stage 3 — Self-pseudolabeling

Serve the Stage-2 checkpoint with vLLM:

```bash
CUDA_VISIBLE_DEVICES=0 python -m vllm.entrypoints.openai.api_server \
  --model SFT/data/Qwen3-1.7B-Base_SFT/checkpoint-XXXX \
  --port 9995 --tensor-parallel-size 1
```

Then run `data_prep/pseudolabel.ipynb` once per teacher (set
`DATASET_NAME = "hermes" | "haiku" | "deepseek"` at the top). Each run reads
the raw teacher CSVs, sends every note back through the labeler, and writes
`data/<teacher>/<teacher>_pseudolabeled.csv`.

### Stage 4 — Combine + augment

`data_prep/combine.ipynb` with `PSEUDO_LABEL = True`:

1. Reads all three `<teacher>_pseudolabeled.csv` files.
2. Drops gibberish / malformed rows via `pipeline.data.preprocessing.preprocess_text`.
3. Applies a stack of label-preserving augmentations
   (`pipeline.data.augmentations`) — date format permutations, name spellings,
   phone-number separators, etc. Each augmentation runs with a per-field
   probability and may be wrapped in a `OneOf` group so a single field
   samples a transform proportional to weight.
4. Splits into 80/20-ish train/test with the last 404 rows held out.
5. Writes `data/train.csv` and `data/test.csv`.

### Stage 5 — Final SFT (0.6B student)

`SFT/sft.ipynb` again, this time with `MODEL_NAME = "Qwen/Qwen3-0.6B-Base"`.
Output → `SFT/data/Qwen3-0.6B-Base_SFT/`. Training-relevant config:

| Setting              | Value                                       |
|----------------------|---------------------------------------------|
| Loss                 | Completion-only (TRL `SFTTrainer`)          |
| Optimizer            | `adamw_torch_fused`, lr=5e-5                |
| Schedule             | warmup → stable → decay (TRL `wsd`)         |
| Precision            | bf16 + Liger kernels + grad checkpointing   |
| Max length           | 8192                                        |
| Eval / save strategy | Per-epoch                                   |

The notebook also calls `pipeline.training.expand_tokenizer` to add the XML
PHI tag tokens (`<phi_entities>`, `<name>`, `<date>`, …) to the tokenizer
and resize the model's embedding table accordingly.

### Stage 6 — Quantize and serve

Convert the safetensors checkpoint to GGUF and quantize:

```bash
# Inside llama.cpp
python convert_hf_to_gguf.py \
    /path/to/SFT/data/Qwen3-0.6B-Base_SFT/checkpoint-XXXX \
    --outfile Qwen3-0.6B-Base_SFT-BF16.gguf --outtype bf16

./build/bin/llama-quantize \
    Qwen3-0.6B-Base_SFT-BF16.gguf \
    Qwen3-0.6B-Base_SFT-Q4_K_M.gguf Q4_K_M
```

Then run the demo:

```bash
python demo/cli_anonymizer.py --model /path/to/Qwen3-0.6B-Base_SFT-Q4_K_M.gguf
```

`demo/cli_anonymizer.py` shells out to `llama.cpp/bin/llama-cli` (compile
`llama.cpp` separately and either copy the binary into `demo/llama.cpp/bin/`
or pass `--model` with an absolute path).

## Evaluation

`evals/` contains two evaluation notebooks:

- **`synth_eval/synth_eval.ipynb`** — held-out synthetic test set
  (`data/test.csv`).
- **`ext_eval/en_eval.ipynb`** — public English benchmark
  (`evals/ext_eval/en_data.csv`, included).

Outputs include per-tag precision/recall/F1 (`*.xlsx`) and Plotly composite
performance dashboards (`*.html`). The companion `synth_eval_inst.ipynb`
evaluates the instruct variant of the student.

## Tips & troubleshooting

- **Tokenizer expansion** — the SFT notebooks call `expand_tokenizer` only
  for the Qwen3 family. If you swap in a different base model, either remove
  that call or extend `pipeline.training.expand_tokenizer.py` for your
  tokenizer family.
- **Augmentation reproducibility** — augmentations are seeded via
  `random.seed(2025)` in `combine.ipynb`. Bump the seed if you want a
  different sample of transforms.
- **vLLM server for pseudolabel** — the notebook hits `localhost:9995`. If
  you change the port, update the `OpenAI(base_url=...)` line in cell ~13 of
  `pseudolabel.ipynb`.
- **`prompts.txt` vs `pipeline.prompts.SYSTEM_PROMPT`** — these must stay in
  sync. The CLI demo loads the former (because it ships independently);
  every notebook imports the latter.
